# mastery-loop 初始化

给 `mastery-loop` 铺好它假设的那套配置。**只跑一次**，之后 `mastery-loop` 直接用你建好的东西。

**产出的 6 个文件**（**全部落在知识库根目录**，文件名固定）：

| 文件名 | 作用 |
| --- | --- |
| `ledger.md` | 复习账本（进度 + 「首次对齐已完成」凭据） |
| `index.md` | 主题 → 知识点的反向索引（可重建缓存） |
| `errors.md` | 错误原因表（真值） |
| `paper-format.md` | 每个课程的每个考试的卷子格式 |
| `error-taxonomy.md` | 失分原因分类（**初始为空**） |
| `config.md` | 路径 + 每门课的成员选择 + 语言标准 |

> 这是**prompt-driven skill，不是确定性脚本**。探索、把发现摆出来、问、确认，然后才写。

---

## 0 · 硬规矩

- **材料目录只读。** 不修改、不移动、不重命名用户给的任何课程材料。
- **只写这 6 个文件**（+ 刷新 MOC 清单，如果库里有 MOC）。**不动知识点笔记的定义部分**。
- **写之前先给草稿让用户过目**（第 6 步）。
- **不含任何真实路径进 skill 包** —— 真实路径只写进用户的 `config.md`。

---

## 1 · Explore（先看，别假设）

- **材料**：用户给的课程目录下有什么？**先列实际目录，不要拿一份固定清单去套** —— 各课结构不同，有的课压根没有往年卷。
- **笔记库**：有没有已存在的知识库？有没有 `MOC/`、`知识点/`？frontmatter 有哪些字段？
- **是否已经初始化过**：`ledger.md` 在不在？**在的话先停下问用户**「要重新初始化，还是只补缺的」。
- **git**：知识库是 git 仓库吗？（只影响要不要提醒用户 `config.md` 含真实路径）

## 2 · 素材：两个类别

**必需的只有两个类别**，不是两个确定的文件：

| 类别 | 用来 | **默认成员** | 类里其他合格成员 |
| --- | --- | --- | --- |
| **建库参考** | 建知识库 | **课程讲义** | 教学大纲 / `exam_topics` / 课件 / 教科书章节 |
| **出题参考** | 出题与判分 | **往年试卷** | 往年卷答案 / Lab sheet / Worksheet / Assessment 结构 |

**判定分两级**：

1. **某一类整类为空** → 真·缺必需项，告诉用户缺什么、去哪找
2. **类里有内容、但没有默认成员** → **不算缺**，只需问一句「用类里另一样顶吗」

**换成员必须问，不能默认。** 用户定了之后**记进 `config.md`**，之后不再问。

> 同时问一句：**「有没有你不想让我读的？」**

## 3 · 语言标准

**按 6 个产物类别分别问**（用户可以用自然语言回答，比如「全都中英双语对照」）：

1. 知识点笔记（正文 / 标题 / `aliases` / MOC / 索引）
2. 出的题（题干 / 选项）
3. 批改与解析
4. 记录性文件（`ledger.md` 等）
5. 产出（复习清单 / 考前 list）
6. 机制层（frontmatter 字段名 / `config.md`）

> ⚠️ **例外**：`errors.md` 里的**错误原因默认用英文** —— 它要套 ASD-STE100 的规则，不该跟着别的类别走。
> 📌 **不要预设双语。** 有人要法文、有人只要中文，问出来。

## 4 · 融合（用户已有知识库时）

**目标不是把用户的库改成我们的样子，而是融合。改什么都要问。**

- **缺 MOC** → 问用户：「按目录/章节能聚出 N 个主题，**要我替你建 MOC 吗**？」**不建是合法选项**（没有 MOC 时，`index.md` 自己就是那份清单）。
- **字段冲突** → **并存 + 映射**，不要轻易改名（改名会打烂用户已有的查询/模板/Dataview）。有 `章节:` 就保留它，另加 `主题:`，值从它映射过来。
- **`主题` 推不出来**（压根没有讲次/章节概念）→ **先推一版草案**（按目录结构或笔记命名规律聚类），摆给用户改。**别直接问「你的主题是什么」** —— 那问题用户答不上来。
- **不动笔记正文**。新字段是**加**上去的。

## 5 · 卷子格式

**每个课程的每个考试各一条**（期中 / 期末 / in-class / coursework 形状不同，必须分开）。

从材料里抄：时间 / 总分 / 题数 / 题型 / 分值分布，并**记住来源**（抄自哪份文件）。

**没有往年卷时**：先问用户该怎么办。
用户没有更好的主意 → 用**默认出卷法 = 判断题 + 每题说明理由**，并在该条目里写明「无往年卷 → 用默认出卷法」。

## 6 · Confirm and edit

**把 6 个文件的草稿摆给用户过目**，让他改。然后再写。

草稿内容由本 skill 目录下的**种子模板**填充：

- [ledger.md](./seeds/ledger.md) —— 账本
- [index.md](./seeds/index.md) —— 索引
- [errors.md](./seeds/errors.md) —— 错误原因表
- [paper-format.md](./seeds/paper-format.md) —— 卷子格式
- [error-taxonomy.md](./seeds/error-taxonomy.md) —— 失分原因分类（**保持为空**）
- [config.md](./seeds/config.md) —— 配置

**填充要点**：

- `ledger.md`：先铺**全部知识点**，`是否学习过 = 否`、`做对/总共出过 = —`、`熟练程度 = NULL`；**顶部的「首次对齐」标记行写上日期与迁移篇数**
- `index.md`：按 `主题` 字段反向生成（已经算出主题的那些）
- `errors.md`：只写结构，**初始没有条目**
- `paper-format.md`：第 5 步收来的每条考试一格
- `error-taxonomy.md`：**保持空**
- `config.md`：路径、每门课的成员选择、语言标准填满

## 7 · Write

写进**知识库根目录**，用**上面那 6 个固定文件名**。

若有 MOC：**先写 `index.md`，再从索引刷新各 MOC 的「## 知识点清单」** —— **永不反向**。

## 8 · 校验

跑校验脚本，确认 6 个文件真的建好了：

```bash
node scripts/validate.mjs <知识库根目录>
```

**6 个文件都在 = 初始化完成。** 缺哪个就补哪个，别靠感觉。

## 9 · Done

告诉用户：初始化完了，`mastery-loop` 之后会读这些文件；想改直接编 `config.md` 那几个文件；**只有要换素材来源或从头再来时才需要重跑本 skill**。
