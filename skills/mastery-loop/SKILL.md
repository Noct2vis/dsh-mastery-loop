# mastery-loop —— 复习闭环

出题 → 批改 → 再出题，直到**每个知识点的熟练度都达到目标正确率**，最后收成**考前 list**。

---

## 0 · 四条硬规矩

1. **不主动扫库。** 初始化之后只在三种情况下才动知识库：① 读到**不符合要求**的文件 → 处理那**一个**；② 出现**新文件** → 处理；③ **用户主动调用** → 才做。
2. **笔记的定义部分默认不动。** 平时只写 `sys/`（*机器区：账本 / 错误原因 / 关系图 / 状态*）与 `kb/MOC/` 的**机器区**。
   **没有新增或修订知识点时不碰；当知识库的架构本身要改（如关系图重建）时，改写是正当的。**
3. **不声称符合 ASD-STE100。** 错误原因**尽可能按 STE 的规则写**，这是借用它的原则，不是合规声明。
4. **脚本只做机械重复的事。** 校验、渲染、聚合、哈希比对、账本运算交给 `scripts/`（Node，零依赖，`node xxx.mjs`）；**判断谁是谁的前置、写理由、出题、批改、错误原因逐字去重**留给自己。**不自动 `commit`、绝不 `push`。**

---

## 1 · 入口

### 1.1 先确认初始化过

读 `sys/config.json` → 找**工作区根** → 读 `sys/ledger.jsonl`。

- **`sys/ledger.jsonl` 不存在** → **停下来**，告诉用户：

  > 这个知识库还没初始化过。先跑一次 `/mastery-loop-setup`，它会把 `kb/` 与 `sys/` 建好，之后我再开工。

  **不要自己进初始化流程** —— 那件事归 `mastery-loop-setup`。

- 初始化过 → 继续。

### 1.2 读状态

顺序固定：

```
sys/config.json（路径 + 分类 + 语言标准）
   → sys/ledger.jsonl（进度）
   → sys/paper-format.json（本次考试的格式）
```

然后**把读到的状态摆出来**：

- **一段话**：「你上次复习到 X，本次范围内 Y 个知识点，已达标 Z 个。」
- **一张小表**：本次范围的知识点按熟练度排序，标出「样本不足」和 `NULL` 的。

### 1.3 与用户确认 —— **用提问窗口，逐步问**

⚠️ **不许把问题堆成一条消息。** 拉起**交互式提问窗口**，**一次一问**：

1. **状态确认** ——「我查到你复习到这一步，对吗？」
2. **本次范围** ——（建议一次一门课，但**范围由用户定**）
3. **本次目标正确率** ——（推荐 90%）
4. **是否跨课程混合考** —— **仅当范围跨多门时**才问（**默认不混合**）

---

## 2 · 环境勘察

**顺序：问 → 读 → 确认匹配度。**

1. **问**：这次要读什么 / 你手上有哪些。**先问，不扫盘猜。**
2. **读**：按用户指的去读，**不预设文件类型**（别写死 `.pdf`）。
3. **确认匹配度**：把结论摆出来，逐条说清 —— 哪些**匹配**、为什么；哪些**不匹配**、为什么；还**缺**什么、**去哪找**。
   - **要写出具体后果**（「判分会偏松」，不是「缺少答案」）；**不必把文件列全**；判定标准只有一条：**两个类别都有着落**。
   - 问一句：**「有没有你不想让我读的？」**
4. **缺默认成员时**问用户是否用类里别的成员顶（**换成员必须问**）。**某一类整类为空**才是真缺必需项。

> 每门课的**第一讲**（`W1L1 Introduction to the Unit` / `Unit organisation` 这类）通常就是**考试边界的来源** —— 哪些考、哪些不考。

---

## 3 · 复习循环

### 3.1 先给复习清单

按 `sys/ledger.jsonl` 排：**熟练度低的在前**，`NULL`（没学过）和「样本不足」标出来。

### 3.2 出题

**卷子参数从 `sys/paper-format.json` 查**对应考试的那一条 —— **不要从往年卷现抄**。
查不到 → 用**默认出卷法：判断题 + 每题说明理由**。

配比（按本次范围的题池算，不按课程切分）：

| 占比 | 打什么 |
| --- | --- |
| 60% | 熟练度最低的点 |
| 30% | `是否学习过 = 否` 的点 |
| 10% | `最后复习日期` 最久远的点（防遗忘） |

卷子模板 → [exam-templates.md](exam-templates.md#试卷模板)。

### 3.3 每题后面必须挂两行

**不分题型，思维链是必写的。** 每道题后面就是这两行，别的都不要：

```
答案：
思维链：
```

- **选题也要写** —— 有足够的推导过程即可，**不强制把所有选项都写出来**。
- 用户不写思维链 → 那一题**无法判定**，记「**未判**」、**不入账本**，并**提示他补写**。

### 3.4 批改 —— 顺序不能反

```
① 先确认思维链的逻辑对不对
② 再确认答案对不对
③ 只要错的个数 ≥ 1  →  才去提炼并规范化错误原因
```

- **做对 = 思维链对 且 答案对。** 任一不对 = 错 —— **蒙对不算对**。
- 两样都错 = **错 2 个** → 很可能要提炼出**两条**错误原因（复合错误要拆）。
- 两个都对 → 不走第 ③ 步。

**批改产出三块**：

1. **评分表** —— 逐题「你的判断 vs 正确答案」+ 得分 + 失分点 + 总分与正确率
2. **详细解析** —— 引用材料原文逻辑；计算题给完整中间步骤
3. **薄弱点定位** —— 说清**为什么错**（从思维链里看），别笼统说「理解不到位」

判分口径 → [exam-templates.md](exam-templates.md#判分口径)。

### 3.5 提炼错误原因（只在错 ≥1 时）

写法**按 ASD-STE100 的规则**（**英文**）：

- 句式优先 **`把 A 当成 B`**（概念混淆类，**必须写出 A 和 B**）；其余用 **`<动作> + <对象>`**
- **一句只写一个偏移** —— 出现 `and / but / because / so / then` 就是两个命题，拆开
- **≤20 词**；**名词短语 ≤3 词**
- **不写**题号、数字、时间词、第一人称、情绪词
- **动词开头**且**必须带对象**（禁 `wrong`、`didn't know`）
- **指代不悬空**

然后**去 `sys/errors.jsonl` 里查**：

1. **在该知识点分组内全量检索**
2. 有**逐字一样**的 → **只追加日期**，**绝不重新措辞**
3. 没有 → 新增一条

### 3.6 写回（顺序写死，不许反向；契约正文 → [templates.md](templates.md)）

- **关系图** —— 本次**若新增或修订了知识点**：先改 `sys/graph.json`（逻辑定前置 → 写边与 ≤30 字理由），再由 `graph.mjs` 算后置并渲染 `## 前置知识` / `## 后置知识`，最后跑六项校验。**没动知识点就跳过这一步。**
- **账本** —— 你只输出字段（做对 / 总共出过 / 熟练程度 / 最后复习日期 / 是否学习过），由 `ledger.mjs` 写进 `sys/ledger.jsonl`。（`做对` 只在**思维链对且答案对**时 +1。）
- **错误原因** —— 逐字去重由**你**做（脚本会把「把 A1 和 B 弄混」和「把 A2 和 B 弄混」误判成重复），写完让脚本写进 `sys/errors.jsonl`。
- **`kb/MOC/` 的机器区** —— 跑 `aggregate.mjs` 从「`归属` + 图」聚合；**手写区一个字不动**。

### 3.7 达标与继续

**达标是逐点判断的**（不是单轮卷面分）：

```
一个知识点达标  ⇔  总共出过 ≥ 5  且  熟练程度 ≥ 本次目标正确率
```

`总共出过 < 5` → 标「**样本不足**」：继续出题，**不算达标、也不算失败**。

- 本次范围内**所有**知识点都达标 → **用提问窗口问**用户是否继续
- 继续 → 回到 3.2
- 不继续 → 进第 4 节

### 3.8 考前 list 是**攒出来的**，不是最后生成的

**从第一轮批改就开始攒。** 每轮出错，就把该点的 `规则 / ⚠️ 常见错误 / 🔑 锚` 三行补进去 —— 出错的那一刻正是信息最鲜活的时候。到复习结束时，它**已经**是成品。

模板 → [exam-templates.md](exam-templates.md#考前-list)。

---

## 4 · 产出：考前 list

**独立成文**（一篇 Markdown 笔记，放在 `kb/` 下）。**只收出过错的点**，按知识点一条，三行结构：

```
### <知识点>
> **规则**：<正确说法>
> ⚠️ **常见错误**：<我实际犯的错>
> 🔑 **锚**：<一句话记忆钩子 / 反例>
```

末尾附「**考前 15 分钟速查**」：最致命的 N 条，一行一条。

## 版本与口径

- 错误原因的写法**借用 ASD-STE100 的原则**，**不声称符合 ASD-STE100**。
- **「同一表述复用」是本 skill 的外推**：STE 只要求「一篇文档内一致」，这里放大成「跨全库、跨时间的去重键」—— **这个外推的责任在本 skill，不在 ASD**。
