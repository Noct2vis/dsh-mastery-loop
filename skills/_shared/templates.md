# 契约正文（Contract）

> **本文件是这套 skill 的契约正文**：库长什么样、每个文件干什么、什么能脚本化。
> `SKILL.md`（*复习主流程*）与 `mastery-loop-setup`（*一次性初始化*）都**只链接到这里**，不各写一份。
> 改契约**只改这个文件**。出题 / 判分 / 考前 list 的模板在 [exam-templates.md](exam-templates.md)。

---

## 一、库的布局

工作区根下**两个并列文件夹**：`kb/`（内容区，给人看）与 `sys/`（机器区，给脚本读）。

```
<工作区根>/
├── kb/
│   ├── knowledge/          # 知识点笔记，一篇一个知识点
│   └── MOC/                # 聚合产物：镜像分类层级
│       ├── 00 总览.md        # 全库视图（可选）
│       └── <类1>/<类2>/…    # 每层一份「该层的索引」，叶子层是讲次级 MOC
└── sys/
    ├── config.json         # 设定：路径 / 分类 / 语言 / 确认标记
    ├── graph.json          # 关系图：必要前置（edges）+ 任一前置组（groups）（真值）
    ├── layers.json         # 分层：派生数据，`check --layers --write` 生成，可随时重算
    ├── graph.html          # 分层图：派生数据，`render-graph.mjs` 生成，浏览器直接打开（可选）
    ├── ledger.jsonl        # 账本：逐知识点的复习统计（真值）
    ├── errors.jsonl        # 错误原因表
    ├── error-taxonomy.json # 失分原因分类（初始为空，agent 维护）
    ├── paper-format.json   # 卷面参数（每个课程的每场考试一条）
    ├── state.jsonl         # 状态：git 模式记提交号；无 git 时逐文件哈希（用于跳过重扫）
    └── reviews/            # 重审清单（`<时间>.md` + `.json`），按需生成
```

**文件夹命名**：固定结构文件夹一律**英文、无特殊符号**（`kb` `knowledge` `MOC` `sys`）。
**类值目录**（`MOC/<类1>/…`）用**用户自己的分类值**（可以是中文）；`config.json` 里给每个类值记一个 **ASCII slug** 供外部工具用。

**每个文件开头一句「本文件是什么」**：

- Markdown：第一行就是这句话；
- JSON：第一个字段是 `"用途"`；
- JSONL：第一行是一条 `{"kind":"header","用途":"…"}` 记录（脚本跳过它）。

## 二、知识点契约

### frontmatter

```yaml
---
类型: 知识点
归属: ["[[Deep Learning/doc/Lecture/W1L1 Introduction to the Unit.pdf|深度学习 L1]]"]
aliases: ["Backpropagation"]
标签: [深度学习, 神经网络, 核心]
---
```

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `类型` | `知识点` | 结构化字段，不是标签 |
| `分类` | **类路径，多值** | **生成这篇知识点时就附上**（哪个类、哪个子类）。一条一个类路径，层级用 `分类.分隔符`（默认 `/`）分隔。脚本**只读这个字段**做聚合，不解析路径 |
| `归属` | **来源文件，多值，必填** | 这个知识点**出自哪份资料**（PDF / DOCX / 网页快照都算）。元素是带路径的 wikilink + 人类可读别名 |
| `aliases` | 英文名列表 | Obsidian 原生别名 |
| `标签` | 既有标签 | 既有标签（用于搜索/标签面板） |

**铁律**

- **没有 `课程:`、没有 `主题:`、没有 `难度:`** —— 课程与讲次是**从 `归属` 解析出来的**（见第四节），不是存的字段。
- **`归属` 是「来源」，不是「关系」** —— 前置/后置在 `sys/graph.json` 里。
- **列表字段不止 `归属`** —— `标签`、`aliases` 同样是列表。
- frontmatter 里的 **wikilink 必须加引号**（`[` 会被 YAML 当数组开头）。
- **契约之外的字段原样保留**，不清理。

### 正文（固定顺序）

```markdown
# <中文名> <英文名>

## 一句话
## 核心内容
## 前置知识
## 后置知识
## 易错点 / 考点
## 讲义出处
```

- `## 前置知识` = **逻辑判定**，唯一判据：**删掉它，本篇的核心内容就解释不通**（只收**直接**前置）。
  - **必要前置**（AND）一条一行：`- [[X]] —— <理由>`；
  - **任一前置组**（OR）合并成一行：`- [[X]] 或 [[Y]]（任一） —— <理由>` —— 组内**满足其一**即可，不要求全学。
- `## 后置知识` = **由图反算，绝不手写**（脚本渲染）；OR 组的每个选项都算后置。
- 每条后面带 `—— <理由>`，与 `graph.json` 里的 `reason` **逐字一致**。
- **没有 `## 平行关联`**。

### 链接写法

- **一律带路径**，**相对工作区根**（= Obsidian vault 根），**带后缀**，**带人类可读别名**：
  `[[kb/knowledge/梯度.md|梯度]]` · `[[Deep Learning/doc/Lecture/W1L1 ….pdf|深度学习 L1]]`
- 代价：改名 / 搬目录会断链 —— 由 `scan.mjs`（*扫库脚本*）发现、`rewrite-links.mjs`（*重写链接脚本*）修。

## 三、关系图 `sys/graph.json`

```json
{
  "用途": "本文件是知识点关系图：edges 是必要前置，groups 是任一前置组。",
  "规则": "边：删掉 from，to 的核心内容就解释不通；只收直接前置。组：组内任一项单独就足以支撑 to。",
  "version": 2,
  "updatedAt": "2026-11-08 18:00",
  "coverage": { "深度学习": { "done": ["L1"], "todo": ["L2"] } },
  "edges": [
    { "from": "梯度", "to": "最速下降与参数空间", "reason": "没有梯度就没有下降方向", "reviewedAt": "2026-11-08", "fp": "sha1…" }
  ],
  "groups": [
    { "id": "g1", "to": "支持向量机", "mode": "any", "of": ["拉格朗日对偶", "核技巧"], "reason": "两条路任选一条" }
  ]
}
```

- **两种依赖语义**：`edges` = 必要前置（AND，全部都要）；`groups` = 任一前置组（OR，满足一个即可）。一个点可以同时有两者，组与组之间默认 AND。
- **边不带课程** —— 课程归属由知识点的 `归属`/标签解析，依赖只是纯逻辑。
- `reason` **≤30 字**，指出依赖的**那一步**。
- `reviewedAt` / `fp` 是重审缓存（内联，可缺省）：上次审过的日期、两端内容 + reason + 判据版本的指纹。
- `coverage`：**按分类层级**记「哪些做完了、哪些没做」。
- 图**允许分批**：`coverage` 里没做的部分，校验不报错。

## 四、分类与范围

**分类是全库级定义**（层级与类值记在 `sys/config.json`），但**每篇知识点属于哪个类，是在生成这篇知识点的时候就附在它身上的** —— 存在 frontmatter 的 `分类` 字段里。**脚本只读这个字段做聚合**，不解析路径、不猜、不写正则。

```yaml
分类: ["深度学习/L3", "机器学习/L5"]   # 一条一个类路径；层级用 `分类.分隔符`（默认 /）分隔
```

`config.json` 里记：

```json
"分类": {
  "层级": ["课程", "讲次"],
  "字段": "分类",
  "分隔符": "/",
  "类值": {
    "课程": [ { "值": "深度学习", "slug": "dl" } ],
    "讲次": [ { "值": "L3", "slug": "l3" } ]
  },
  "确认": "（用户于 <YYYY-MM-DD HH:MM> 确认）"
}
```

- **一篇可以属于多个类**（`归属` 是多值的，类也跟着多值）；
- **归类在生成知识点时定**，不由后面的脚本推；规则怎么算、按什么分，由 agent 在 setup 时**看这个库**再和用户确认（**不预设形状**：课程 / 章 / 模块 / 主题都行）；
- **范围 = 分类里的一个或多个类路径**（例：`深度学习/L3`），脚本按它筛。

## 五、聚合与两区

`kb/MOC/` 下的一切都是**从 `归属` + 图聚合出来的**，不是手写枚举。每份 MOC / 索引里分两区：

```markdown
<!-- AUTO:BEGIN -->
- [[kb/knowledge/梯度.md|梯度]] —— ∇J 是代价函数对全部参数的一阶偏导向量
<!-- AUTO:END -->

## 主线（手写区）
```

- **机器区**：`aggregate.mjs`（*聚合脚本*）生成与覆盖（按分类层级列 `- [[链接]] —— 一句话`、覆盖进度）。
- **手写区**：agent / 人写，**脚本永不碰**（主线、脉络、指定阅读、考点提示）。
- 聚合脚本**只做聚合**：不写待办、不打印摘要 —— **要说话的是 `scan.mjs`**。
- 「分组」不是独立概念：**分类有几层就分几层**；只有两层时 MOC 内部不再分组。

## 六、脚本边界

**脚本只做重复性、机械性、不需要变通的事。** 要理解内容、要随机应变、要交互的**留给 agent**。

| 脚本 | 干什么 | 谁触发 |
| --- | --- | --- |
| `graph.mjs` | 读写 `sys/graph.json`；八项校验；算分层（`--layers`）；由图渲染两段 | agent |
| `render-graph.mjs` | 读 `graph.json` + `layers.json` + `分类`，生成 `sys/graph.html`（自包含，给人看） | agent（想看时） |
| `review.mjs` | 重审候选（指纹 / 邻域 / 老化）、写清单、盖 `reviewedAt`/`fp` | agent |
| `aggregate.mjs` | 从 `归属` + 图聚合 MOC / 索引的**机器区** | agent |
| `scan.mjs` | 扫库六项（见第七节；链接**只查 `kb/`**）；读 `state.jsonl` **按哈希跳过没变的**；发现坏链接就提示跑 `rewrite-links.mjs` | agent |
| `rewrite-links.mjs` | 改名 / 搬目录后重写所有带路径链接 | agent（由 scan 触发） |
| `ledger.mjs` | 按 60/30/10 筛清单、算达标、**批改写回**、`add` 新点、`next` 按层序找下一个没学的点 | agent |
| `validate.mjs` | 查 `kb/` 与 `sys/` 的结构是否齐 | agent / setup |

**不能脚本化**（明确留 agent）：判断谁是谁的前置、写 `reason`、出题、批改、**错误原因去重**（脚本会把「把 A1 和 B 弄混」和「把 A2 和 B 弄混」误判成重复）、frontmatter 规范化、分类协商。

**脚本纪律**：Node（零依赖，`node xxx.mjs`）；**不拼 shell**（路径含中文 / 空格）；只读写自己那类文件。

`config.排除` 是**给人/agent 读的阅读排除清单**（哪些材料不要读），脚本**不读**它。

## 七、校验

### 图（`graph.mjs check`，八项）

| # | 名称 | 判据 |
| --- | --- | --- |
| 1 | 双向自洽 | 边 / 组 ⟺ 正文对应行；正文里出现的关系必须在图里有对应结构 |
| 2 | 无自链 | 没有 `from == to`；组内不出现 `to` |
| 3 | 无悬空 | `from` / `to` / `of` 都能找到对应笔记 |
| 4 | 同段无重复 | 同一小节里同一目标只出现一次 |
| 5 | 前后置互斥 | 同一篇的前置集合 ∩ 后置集合 = ∅ |
| 6 | 前置两两不可比 | 必要前置（AND）之间不可互为前置/后置（只收直接前置） |
| 7 | 无环 | 全图（含组边）无环；失败时打印环路径 |
| 8 | 组结构 | `of` 非空、`mode` 为 `any`、组 id 唯一、组内选项两两不可达（否则是假 OR） |

**分层**：`depth(v) = 0`（无依赖）；否则 `1 + max(AND 依赖深度)`，OR 组取 `1 + min(组内选项深度)`。

### 扫库（`scan.mjs`，六项）

链接检查**只覆盖 `kb/` 里的笔记**；库外（其他课程资料、copilot 记录、AGENTS.md 模板占位符）的链接归 Obsidian，本插件不报。

① 悬空链接（`kb/` 内）② 带路径链接与当前目录结构不符（`kb/` 内）③ `config.json` 的分类 / 版本与现状不符 ④ 图与笔记两段不一致（= 图校验）⑤ 账本 / 错误原因里引用的知识点是否还存在 ⑥ `归属` 指向的来源文件不存在（归属缺失）。

## 八、排序（可选，不是契约）

本机**若装了 Miyo**，可以在**已按知识深度排好之后**，对「深度上并列、拿不准先后」的条目问一次相关度作参考：
`POST http://127.0.0.1:8742/v0/search/related`，body `{"file_path":"<已注册 folder 名>/<库内相对路径>","limit":N}`。

- **知识深度是定序者**，Miyo 只作参考；分数**不写进** frontmatter / 图；
- **没装就跳过**：不报错、不检查、不阻塞 —— 发布版**不依赖** Miyo；
- 实测提醒：`file_path` 三种分隔符都能用；真正 404 的是「缺已注册 folder 前缀 / 绝对路径 / 不带 `.md` / 路径不在索引里」。

## 九、git 与历史

**能用 git 就用 git** —— 这条管两件事，都优先走 git：

| 要回答的问题 | 有 git | 没有 git（且用户不装） |
| --- | --- | --- |
| **哪些文件变过**（决定要不要重看） | `git status` + 上次检查的提交号之后 `git diff` | `sys/state.jsonl` 里逐文件的内容哈希 |
| **发生过什么**（决定怎么追溯） | git 历史（skill **不自动 `commit`、绝不 `push`**，只提示） | **没有兜底** —— 没有 git 就没有历史，请自行备份 |

- `sys/state.jsonl` 在 git 模式下**只有一行**（`{"mode":"git","last":"<commit>",…}`）；没有 git 时才逐文件记哈希；
- 变化检测覆盖 `kb/` 的 Markdown 与 `sys/` 的 JSON / JSONL（改图、改配置也算「变过」）；
- 管「要不要重看」的是它，管「发生过什么」的是 git —— **两者不是一回事**；
- 沙箱里抓子进程输出会被拒（EPERM），所以脚本调 git 时把输出**重定向到文件描述符**再读回来，而不是用管道。

## 十一、复习循环里用到的量

- **配比**（按本次范围题池统算）：60% 熟练度最低 · 30% `是否学习过 = 否` · 10% `最后复习日期` 最久远。
- **熟练度**（逐点）：`(做对 + 0.5) / (总共出过 + 1)`（Jeffreys）。4/4 = 90.0%，3/4 = 70.0%，1/1 = 75.0%。
- **达标**（逐点）：`熟练程度 ≥ 本次目标正确率`（默认 0.9）。**没有「总共出过 ≥ 5」的硬阈值。**
- **样本不足**：只做展示（`总共出过 < 3`），不是独立判据。
- **账本字段**：`知识点 / 是否学习过 / 做对 / 总共出过 / 熟练程度 / 最后复习日期`。
- **做对** = 思维链对 **且** 答案对（蒙对不算）。

## 十二、错误原因表 `sys/errors.jsonl`

一条一个 JSON 行；首行是 `{"kind":"header","用途":"…"}`。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `kind` | 是 | `"error"` |
| `知识点` | 是 | 被考的那个点（考点） |
| `谓词` | 是 | `confuse / overgeneralize / misorder / omit / invert / misapply / miscompute / notation / other` |
| `涉及` | 是 | 数组；跨点混淆填另一篇，否则 `[]` |
| `方面` | 否 | 自由短标签（定义 / 方向 / 条件 / 公式 / 顺序…） |
| `错误原因` | 是 | 英文原句，展示用；逐字复用 |
| `中文` | 否 | 中文对照 |
| `日期` | 是 | 数组，`YYYY-MM-DD` |
| `来源` | 否 | 卷子 / 轮次 |

- **去重键** = `(谓词, 涉及集合, 方面)`；原文只用于展示，不参与比较。
- **跨点混淆只写一条**：挂在 `知识点`，`涉及` 指向另一篇；两个点都渲染它，统计只算一次。
- **新增前先列候选**（该点 + 涉及该点的记录），没有选中再走结构键，仍没有才新增。
- 写法借用 ASD-STE100：一句一个偏移、≤20 词、动词开头、不写题号/数字/时间/第一人称。

## 十三、图的定期重审 `review.mjs`

**触发**：一批入库写完之后、或用户手动要求；**没有定时器**。**改图满 5 次强制一次全量**：有 git 时数 `sys/graph.json` 的提交数，无 git 时数两次 plan 之间图的哈希变化。

**三个信号**（脚本只负责找候选，判定留 agent）：

| 信号 | 谁算 | 说明 |
| --- | --- | --- |
| 指纹变过 / 从未审过 | 脚本 | `fp = sha1(from 正文 + to 正文 + reason + 判据版本)`，内联在边/组上 |
| 邻域内出现新点 / 改点 | 脚本 | 新点 ±2 跳内的旧边全部重看 |
| 超过 90 天未审 | 脚本 | 老化轮转，防止一条边永远不被看 |

**为什么可以不全判**：「全量」指**覆盖所有边**，不是每条都重新推理；内容没变的边复用上次结论，变过的、邻域内的、老化的才进清单。强制全量用 `--force`。

**流程**（脚本不直接改图）：

```bash
node review.mjs plan <根>                 # 写 sys/reviews/<时间>.md / .json
# agent + 用户逐条判「删掉它，目标还解释得通吗？理由是否说出那一步？」
node review.mjs mark <根> --file <确认清单.txt>   # 一行一条 id；--full 表示这次审完
node graph.mjs check <根>                 # 改过图就重跑八项
```

- 清单里的 id：边写 `A → B`，组写 `g1`；
- `mark` 只盖 `reviewedAt` / `fp`，不判断、不删边；
- 「这条边不对」的结论由 agent 写进清单建议，用户确认后才改 `graph.json`。
