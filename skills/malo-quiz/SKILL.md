# malo-quiz —— 考试循环

出题 → 批改 → 再出题，直到**每个知识点的熟练度都达到目标**，最后收成**考前 list**。

## 0 · 四条硬规矩

1. **不主动扫库。** 只在三种情况下动知识库：读到不合规文件、有新文件、用户主动要求。新文件归 `/malo-intake`。
2. **笔记的定义部分默认不动。** 平时只写 `sys/` 与 `kb/MOC/` 的机器区。
3. **不声称符合 ASD-STE100。** 错误原因尽可能按 STE 的原则写，不是合规声明。
4. **脚本只做机械事。** 校验、渲染、聚合、账本运算、错因查询交给 `../_shared/scripts/`；判断前置、出题、批改、选错因留给自己。**不自动 commit、绝不 push。**

## 1 · 入口

### 1.1 版本闸

读 `sys/config.json` 的 `schema_version`，与 `../_shared/scripts/_lib.mjs` 的 `LIB_VERSION` 比：

- 相等 → 继续；
- 库版本 < 技能版本 → **停**：「库版本 X，技能版本 Y；先按 CHANGELOG 的 `### 迁移` 升级，再回来」；
- 库版本 > 技能版本 → **停**，提示升级插件包。

### 1.2 读状态

顺序固定：

```
sys/config.json（路径 / 分类 / 语言 / 闸门）
  → sys/ledger.jsonl（进度）
  → sys/paper-format.json（本次考试的卷面）
```

摆给用户：

- **一段话**：「你上次复习到 X，本次范围内 Y 个知识点，已达标 Z 个。」
- **一张小表**：本次范围按熟练度排序，标出 `样本不足`（`总共出过 < 3`）和 `NULL`。

### 1.3 与用户确认 —— 用提问窗口，一次一问

1. 状态确认；
2. 本次范围（分类类路径；建议一次一门，但范围由用户定）；
3. 本次目标正确率（默认 0.9）；
4. 是否跨课程混合考（仅当范围跨多门时问，默认不混合）。

## 2 · 范围与覆盖率

- **前置闭包**：从用户选的范围出发，沿 `sys/graph.json` 的前置边递归，闭包内的点**都纳入达标**；若图有 `groups`（OR 前置），组内任一满足即可，不要求全学。
- **覆盖率**：本次范围内 `是否学习过 = 否` 的比例；超过 `config.覆盖率阈值`（默认 0.3）→ **警告并放行**，提示可以先跑 `/malo-study`。
- **出题闸门**：`config.闸门.出题`（默认 `仅首轮`）。首轮出卷前，把「题型 / 题数 / 60-30-10 配比 / 覆盖哪些点」摆给用户。

## 3 · 出题

**卷面参数从 `sys/paper-format.json` 查**对应考试的那一条，不要从往年卷现抄。查不到 → 默认出卷法：判断题 + 每题说明理由。

配比（按本次范围题池统算）：

| 占比 | 打什么 |
| --- | --- |
| 60% | 熟练度最低的点 |
| 30% | `是否学习过 = 否` 的点 |
| 10% | `最后复习日期` 最久远的点 |

模板 → [`../_shared/exam-templates.md`](../_shared/exam-templates.md#试卷模板)。

## 4 · 每题后必须挂两行

不分题型，思维链是必写的：

```
答案：
思维链：
```

- 选择题也要写，有足够推导即可，不强制列全选项。
- 用户不写思维链 → 该题**未判**、不入账本，提示补写。

## 5 · 批改 —— 顺序不能反

```
① 先确认思维链的逻辑对不对
② 再确认答案对不对
③ 只要错的个数 ≥ 1 → 才去提炼并规范化错误原因
```

- **做对 = 思维链对 且 答案对。** 任一不对 = 错，蒙对不算对。
- 两样都错 = 错 2 个，很可能要拆成两条错误原因。

批改产出三块：

1. **评分表**：逐题「你的判断 vs 正确答案」+ 得分 + 失分点 + 总分与正确率；
2. **详细解析**：引用材料原文逻辑；计算题给完整中间步骤；
3. **薄弱点定位**：从思维链里说清为什么错，不要笼统写「理解不到位」。

判分口径 → [`../_shared/exam-templates.md`](../_shared/exam-templates.md#判分口径)。

## 6 · 提炼错误原因（只在错 ≥ 1 时）

写法**按 ASD-STE100 的原则**（英文）：

- 句式优先 `把 A 当成 B`（混淆类必须写出 A 和 B）；其余用 `<动作> + <对象>`；
- 一句只写一个偏移；出现 `and / but / because / so / then` 就拆开；
- ≤20 词；名词短语 ≤3 词；
- 不写题号、数字、时间词、第一人称、情绪词；
- 动词开头且必须带对象；指代不悬空。

**记录字段**（契约 → [`../_shared/templates.md`](../_shared/templates.md#十二错误原因表-syserrorsjsonl)）：

```json
{"kind":"error","知识点":"梯度","谓词":"confuse","涉及":["学习率"],"方面":"方向",
 "错误原因":"Confuse the gradient with the step size.","中文":"把梯度当成步长。",
 "日期":["2026-11-08"],"来源":"DL 期中格式卷 2 · Q3"}
```

- 谓词：`confuse / overgeneralize / misorder / omit / invert / misapply / miscompute / notation / other`；
- **去重键 = `(谓词, 涉及集合, 方面)`**，原文不参与；
- **跨点混淆只写一条**：挂在被考的点，`涉及` 指向另一篇；两个点都渲染它，统计只算一次；
- 顺序：**先列候选**（`errors.mjs query <点>`）→ 用户选 → 没选中再走结构键 → 仍没有才新增。

## 7 · 写回 —— 与批改是同一个动作

批改完**先出确认页**，再写盘：

- 评分表；
- 账本 delta（每个点 `做对 / 总共出过` 各 +几、`是否学习过`、日期）；
- 新增错因的逐字原文（单独列一块，因为它是复用键）。

闸门：`config.闸门.批改写回`（默认 `每次`）。用户确认后一次写入：

```bash
node ../_shared/scripts/ledger.mjs write <根> <updates.jsonl>
node ../_shared/scripts/errors.mjs add  <根> <new-errors.jsonl>
```

顺序写死：**图（若本次新增/修订了知识点）→ 账本 → 错因 → MOC（若动过知识点）**。本 skill 通常不动图。

## 8 · 达标与继续

- **熟练度 = `(做对 + 0.5) / (总共出过 + 1)`**（Jeffreys）。4/4 = 90%，3/4 = 70%，1/1 = 75%。
- **达标 ⇔ 熟练度 ≥ 本次目标**；没有「总共出过 ≥ 5」的硬阈值。
- `总共出过 < 3` 只标「样本不足」做提示，不改变达标判定。
- 本次范围内所有点达标 → 用提问窗口问是否继续（闸门 `config.闸门.达标后继续`，默认 `每次`）。
- 继续 → 回到第 3 节；不继续 → 第 9 节。

## 9 · 考前 list

**从第一轮批改就开始攒**，不是最后生成。每轮出错，把该点的 `规则 / ⚠️ 常见错误 / 🔑 锚` 三行补进去。

独立成文（一篇 Markdown，放 `kb/` 下），只收出过错的点，按知识点一条：

```
### <知识点>
> **规则**：<正确说法>
> ⚠️ **常见错误**：<我实际犯的错>
> 🔑 **锚**：<一句话记忆钩子 / 反例>
```

末尾附「考前 15 分钟速查」：最致命的 N 条，一行一条。模板 → [`../_shared/exam-templates.md`](../_shared/exam-templates.md#考前-list)。
